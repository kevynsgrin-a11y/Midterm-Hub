# Claim audit of 2026-10-08: what was applied, what was held, what is left

This note is the handoff for the October 2026 claim audit of midtermwatch.com. Part 1 applied the claims the audit marked publication-eligible. Part 2 (2026-10-09) re-verified the claims the audit held, checked every record's "offices on the ballot" list, and closed the site-wide findings that needed code. The note records what went into the data, what was deliberately left out and why, and what to recheck before Election Day. The audit's own files are not in the repository; the maintainer holds the originals (claim-audit JSON, two cross-review JSONs, held-claims CSV, HTML report).

## What "supported" meant, and how it was applied

The audit's "publication-eligible" flag says a claim has two independent, substantively read sources. Part 1 re-read every eligible claim against its cited official source before writing anything. Part 2 applied the same standard to the held claims, state group by state group, with no claim trusted because the audit had listed it. Each result was one of:

- **CONFIRMED2**: two independent official publishers state the value within the claim's scope. Written. (A state PDF and the same state's web page are one publisher; a state office, a county office and the statute itself are three.)
- **CONFIRMED1**: exactly one official publisher states it and that publisher is the controlling authority (the state's own calendar or the statute). Written, and the one-publisher basis is recorded here when it matters.
- **PARTIAL**: the date is right but a scope, time, channel or exception differs. Written only with the verified scope, never the original wording.
- **CONFLICT** or **UNREADABLE**: not written as a single value. A conflict is either stated in the notes with both sources (when voters can act on both) or left out. The item is listed under "Part 2: what was not published" below.

Official sources are the state election authority, statutes and rules on the legislature's or state's own site, county or parish election offices, and federal agencies (FEC, EAC, FVAP, Senate.gov). News, advocacy sites, Ballotpedia, Wikipedia and NCSL are leads only. Pages that returned 403 to ordinary fetches were read through a browser renderer; if that failed the page was recorded as unreadable. The highest-risk quotes were also spot-checked first-hand against the primary source (for example Fla. Stat. 100.011, 101.62, 101.67, 101.6952 and 101.657; the Georgia Secretary of State calendar; the Alaska Constitution art. XI sec. 6; the Arkansas, Kansas and Florida official pages; S.C. Code 7-5-150; RSMo 115.291; the New Mexico General Election Proclamation).

### Mapping into the data model

`ElectionRecord` (`civic/models.py`, `extra="forbid"`) has a small structured surface: `registration_deadline`, `registration_deadline_time` (HH:MM), `early_voting_start`, `early_voting_end`, `mail_ballot_request_deadline`, `candidate_filing_deadline`, `late_registration`, `timezone`, `confidence`, `source_url`, `source_retrieved_at`, `notes`. Rules used:

- A date or time went into a structured field only when it was confirmed for the whole jurisdiction and the field's meaning matched. Where early voting starts on different dates in different counties (for example Georgia, Kansas, Utah, Idaho), the field holds the earliest permitted date only if the state sets one, and the note says so; otherwise it is left empty.
- Anything channel-specific (mail vs online vs in person), conditional, or scoped (military and overseas voters, particular offices) went into `notes`, which the site displays.
- Contradicted sentences in existing notes were corrected rather than appended to.
- `source_retrieved_at` was set to `2026-10-09T12:00:00Z` on records whose facts were re-read that day. Noon UTC keeps the displayed date correct in every US time zone. After Part 2 every record has been re-read, so no record shows "Retrieved 7/21/2026" any more. Do not relabel a record as newly verified without reading its sources.
- Elections already held carry the word "historical" in `notes` (see the archive gate below).
- Historical primaries for states without a primary record were added as a sentence on the general record. No new primary records were created.
- `late_registration` (`none`, `early_voting`, `election_day`, `not_required`) answers "can I still register for this election after the regular deadline?". It is set on general elections only. It is presentation metadata: it travels in the frontend payload, the CSV and the calendar reminder, but the legacy SQLite store does not persist it and it is not in the content hash, so there is no schema migration. Narrow statutory exceptions (for example discharged service members in South Carolina, military and overseas voters in Missouri and West Virginia, newly naturalized citizens in Nebraska) stay in each state's notes and do not change the value. Montana's `election_day` holds only while the SB 490 injunction does (see the recheck list).

## Where the data lives and how to change it

- Source of truth: `intake/2026-statewide.yaml`. Edit single lines in place and keep the existing double-quoted scalars. `offices` is an inline list.
- `generated/elections.json` and `public/downloads/*` are build artifacts. Regenerate them with `python -I scripts/build-frontend-data.py`; never edit them by hand. It keeps `generated_at` when nothing changed. Tests fail if the committed artifacts are stale.
- Before pushing a data change: run the generator (it validates all records with the same Pydantic model), `pytest`, `npm test`, `npm run typecheck`, `npm run lint`, and the legacy renderer pipeline (`civic init`, `civic intake FILE --by editorial --published generated/elections.json`, verify, `civic site build`). For a page-level check run `npm run build` in the main checkout (not in a git worktree whose `node_modules` is a symlink; Turbopack rejects that) and then restore the tracked build output with `git checkout -- out && git clean -fdq out`.
- Live check after a merge: the Vercel deployment serves `/downloads/midterm-watch-elections.json`; its SHA-256 must equal the one in `generated/downloads-manifest.json`.

### The 30-day archive gate

`ElectionRecord` rejects a record whose election was more than 30 days ago unless its notes contain the word "historical", or the record is exactly the one already published. Two consumers apply that rule:

- the frontend exporter (`scripts/build-frontend-data.py`), and
- `civic intake`, used by `scripts/build-site.sh` for the GitHub Pages `deploy-site` workflow.

Until PR #25 only the first knew about "already published", so `deploy-site` failed on 2026-10-09 when the NH primary aged out. Both now share `published_key` / `published_index` in `civic/intake.py`. Consequences:

- An unchanged published record stays valid indefinitely; nobody has to edit data when an election ages out (the DE primary crosses 30 days on 2026-10-16, general-election records on 2026-12-04).
- Editing an aged record in any field, provenance timestamp included, requires adding "historical" to its notes.
- The comparison needs the record to be `verified: true` in `generated/elections.json`, so regenerate that file in the same commit as the YAML.
- A published row that predates an optional model field counts as the same record (a missing key equals `None`), so adding an optional field does not re-open the gate for archived records. Setting that field on an archived record is still a new intake. Both behaviours are tested.

## Recheck before Election Day

- **Montana** late registration until 8 p.m. depends on the injunction against SB 490. If it is lifted or reversed the cutoff can move to noon. Recheck the Secretary of State's federal calendar and votemt.gov weekly. `late_registration: election_day` for Montana depends on the same order.
- **Kansas** mail-ballot receipt depends on the Douglas County injunction. Recheck the Secretary of State's advance-voting page weekly for an appeal outcome.
- **Ohio**: the Secretary of State's schedule requires ballots other than military and overseas ones to be received by 7:30 p.m. on Election Day; the verifier traced the change to Senate Bill 293. A court challenge could change it.
- **Hawaii** register-by is the Office of Elections' published Oct 26. Its rule text still says "tenth day".
- **Mississippi**: the regular Supreme Court election is enjoined by a federal court order; the ballot could change if it is lifted.
- **Missouri**: the Kansas City Election Board's notice says litigation may change the congressional map ("Right now, we must use the 2022 congressional map").
- **Georgia and Florida**: a georgia.gov banner dated 2026-10-08 announces a state of emergency ahead of a hurricane. No election change appeared on the pages read, but county early-voting sites and hours can change.
- **New Hampshire**: the Secretary of State's registration page was revised after an Oct 2 federal court order on student IDs; recheck the documentary-proof wording.
- **New Jersey**: recheck whether a 35th Legislative District General Assembly contest is on the ballot (see above).
- **Louisiana** Dec 12, **Georgia** Dec 1 and **Mississippi** Dec 1 runoffs are conditional; **Arkansas** Dec 1 applies to county and municipal races and to ties.
- Every state where counties set early-voting days (Florida, Georgia, Kansas, Idaho, Utah, Illinois, California): the structured dates are the statewide minimum or earliest permitted day.

## Operations notes

- **What serves midtermwatch.com.** The apex and `www` are Cloudflare Worker custom domains for the `midtermwatch-vercel-proxy` Worker, whose upstream is `https://midterm-hub.vercel.app` (the Vercel project; per the repo history its production deployments track `main`). The Next.js build (`npm run build`) regenerates the payload and downloads in its `prebuild` step, so the committed artifacts and the deployed ones must agree (tests enforce it). The GitHub Pages `deploy-site` workflow builds a separate legacy Python renderer and is not what the domain serves.
- **`Workers Builds: midterm-hub` is red on every PR and on `main`.** The Cloudflare Worker `midterm-hub` has Workers Builds triggers whose root directory is `/dist`, which does not exist in a fresh clone, so every build stops at the clone step with "root directory not found". The Worker serves no traffic (workers.dev disabled, no routes, no custom domain), and the failure predates the audit. It needs a one-time dashboard change (Workers & Pages, `midterm-hub`, Settings, Builds). The assistant session that investigated had read-only access to Workers Builds, so nothing was changed. Original trigger settings, for reference:
  - "Deploy non-production branches": branches `*` except `claude/civic-calendar-engine-backend-wddfqw`, build `bash scripts/build-site.sh dist`, deploy `npx wrangler versions upload`, root `/dist`. This is the trigger that fires on PRs and on `main`.
  - "Deploy default branch": only the branch `claude/civic-calendar-engine-backend-wddfqw` (dormant), deploy `npx wrangler deploy`, root `/dist`.

  Pausing the first trigger (for example by restricting its branch filter to a name no branch has), or disconnecting the repository from that Worker, ends the red check. Do not simply fix the root directory: that would let the build run `wrangler deploy` for a Worker nobody uses.
- **A "reviews: no clone found for source" failure was reported but not located.** It is not among the Workers Builds for `midterm-hub`, the repository's GitHub Actions runs or the account's scheduled routines. If it recurs, note where it appears (a Cloudflare dashboard page, a GitHub check or an email) so it can be traced.
- **Tests that depend on today's date.** `tests/conftest.py` builds a fixture site; its VA record carries a "historical" note for the reason above. A fixture with a recent election date will fail once it ages past 30 days unless it carries one too.
- **Process for another pass.** Group claims by state; give each verifier the repository's current record and the claim list; require a verbatim quote and URL for each verdict; apply only confirmed values; validate; ship one PR per batch with the verifier output summarised; compare the live downloads hash after each merge.
